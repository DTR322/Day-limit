# Документация проекта Day Limit

## 📋 Описание проекта

**Day Limit** — это Vue.js приложение для управления личным бюджетом с фокусом на ежедневные лимиты трат. Приложение помогает пользователям распределять доход на месяц, учитывая обязательные расходы и финансовые цели, и рассчитывает доступную сумму для ежедневных трат.

## 🚀 Технологии

- **Vue.js 3.5.40** - фреймворк с Composition API
- **Vue Router 4.6.4** - маршрутизация
- **Vite 8.2.0** - сборщик проектов
- **vite-plugin-pwa 1.3.0** - поддержка Progressive Web App

## 💾 Хранение данных

Приложение использует **localStorage** для сохранения данных:

### Ключи localStorage:

1. **`daylimit-settings`** - настройки пользователя:
   ```javascript
   {
     income: number,           // Ежемесячный доход
     rent: number,             // Аренда
     utilities: number,        // Коммуналка
     food: number,             // Еда
     transport: number,        // Транспорт
     credits: number,          // Кредиты
     customExpenses: [],       // Пользовательские категории расходов
     savings: number,          // Процент накоплений (0-100)
     goal: string|null,        // ID выбранной цели
     goalName: string|null,    // Название кастомной цели
     goalAmount: number,       // Сумма финансовой цели
     daysToSalary: number,     // Дней до зарплаты
     savingsUsed: number,      // Сколько уже взято из накоплений
     debt: number              // Текущий долг (перерасход)
   }
   ```

2. **`daylimit-transactions-YYYY-MM`** - транзакции за месяц:
   ```javascript
   [
     {
       id: string,             // Уникальный ID транзакции
       name: string,           // Название категории/траты
       amount: number,         // Сумма траты
       date: string            // ISO 8601 дата создания
     }
   ]
   ```

## 🧮 Алгоритм расчёта дневного лимита

1. **Расчёт обязательных расходов:**
   ```
   fixedExpenses = rent + utilities + food + transport + credits + customExpenses
   ```

2. **Свободные деньги:**
   ```
   freeMoney = max(0, income - fixedExpenses)
   ```

3. **Месячный бюджет (после отчисления на цель):**
   ```
   monthlyBudget = freeMoney - (freeMoney * savingsPercent / 100)
   ```

4. **Доступные деньги на текущий момент:**
   ```
   availableMoney = max(0, monthlyBudget + savingsUsed - totalSpentMonth)
   ```

5. **Дневной лимит:**
   ```
   dailyLimit = availableMoney / daysRemaining
   ```

6. **Остаток на сегодня:**
   ```
   remainingToday = dailyLimit - totalSpentToday
   ```

## 🎯 Логика работы с перерасходом

Когда пользователь добавляет трату, которая превышает доступный баланс:

1. Сначала деньги списываются из доступного бюджета
2. Если бюджета недостаточно, разница покрывается из финансовой цели (`savingsUsed` увеличивается)
3. Если цель исчерпана, остаток уходит в долг (`debt` увеличивается)

При удалении транзакции процесс идёт в обратном порядке:
1. Сначала гасится долг
2. Затем восстанавливается финансовая цель

## 🎨 Визуальные состояния

### Карточка лимита
- **Обычное состояние** - градиент фиолетовый (#667eea → #764ba2)
- **warning** (< 1500 ₽) - оранжевый градиент (#ff9800 → #f57c00)
- **danger** (< 500 ₽) - красный градиент (#f44336 → #c62828)
- **overspent** (< 0 ₽) - тёмно-красный с анимацией пульсации

### Прогресс-бар
- **normal** (≤ 50%) - фиолетовый
- **warning** (50-80%) - оранжевый
- **danger** (> 80% или перерасход) - красный

## 🔧 Известные проблемы (баги)

### 1. Критический: Некорректный возврат средств при удалении транзакции
**Файл:** `src/components/MainScreen.vue`, строки 311-328

**Описание:** При удалении транзакции деньги возвращаются сначала на погашение долга, затем в цель. Однако при добавлении траты деньги брались в обратном порядке (сначала из бюджета, потом из цели, потом в долг). Это приводит к несоответствию состояния.

**Решение:** Изменить логику на обратную: сначала восстанавливать цель, затем гасить долг.

### 2. Дублирование CSS-стилей
**Файл:** `src/style.css`, строки 1-81

**Описание:** Стили для селекторов `*` и `body` определены дважды (строки 1-5 и 77-81), что приводит к избыточности CSS.

**Решение:** Удалить дублирующиеся определения (строки 77-81).

### 3. Неиспользуемый импорт
**Файл:** `src/App.vue`, строка 8

**Описание:** Импортируется компонент `RouterView`, но в template используется встроенный `<router-view />`.

**Решение:** Удалить строку импорта `import { RouterView } from 'vue-router'`.

### 4. Отсутствие валидации суммы траты
**Файл:** `src/components/MainScreen.vue`, строки 98-104

**Описание:** Поле ввода произвольной суммы не имеет ограничения на минимальное значение, пользователь может ввести отрицательное число.

**Решение:** Добавить атрибут `min="0"` к input и валидацию в `processCustomTransaction`.

### 5. Необъявленная переменная в StartScreen
**Файл:** `src/components/StartScreen.vue`, строка 318

**Описание:** В функции `finish()` используется `customGoalName.value`, но эта переменная не объявлена в компоненте.

**Решение:** Либо удалить эту строку, либо добавить реактивную переменную `customGoalName`.

### 6. Упрощённый откат при массовой очистке
**Файл:** `src/components/MainScreen.vue`, строки 330-347

**Описание:** Функция `clearTodayExpenses` использует упрощённую логику возврата средств, которая может некорректно распределить деньги между долгом и целью.

**Решение:** Переписать функцию с учётом полной истории транзакций и точного расчёта возврата.
